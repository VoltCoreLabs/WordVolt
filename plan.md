# WordVolt — план разработки

Цель: настольный текстовый процессор (аналог MS Word) на чистом Rust, GPU-рендеринг через GPUI.

## Текущий этап
**Этап 0 — Фундамент** (не начат)

## 1. Объём (scope)
**MVP (v0.1):** абзацы, символьное форматирование (жирный/курсив/подчёркнутый/цвет/шрифт/размер), выравнивание, списки, undo/redo, выделение, буфер обмена, сохранение/открытие `.wvd` и `.docx` (базово), экспорт PDF, постраничный вид, масштаб.
**v0.2:** таблицы, изображения, колонтитулы, номера страниц, стили абзацев, поиск/замена, проверка орфографии.
**v1.0:** сноски, оглавление, комментарии, отслеживание изменений, печать, полный docx round-trip.
**Не делаем:** совместное редактирование онлайн, макросы VBA, мобильные платформы.

## 2. Стек
| Слой | Выбор | Зачем |
|---|---|---|
| UI | **GPUI** (Zed) + **gpui-component** | GPU-рендер, нативная скорость; gpui-component даёт кнопки, меню, диалоги, дерево, вкладки |
| Шрифты/шейпинг | **cosmic-text** | чистый Rust: шейпинг (rustybuzz), fallback, bidi, переносы строк |
| Текст-буфер | **ropey** (на уровне абзаца) | быстрые вставки/удаления |
| Графемы/Unicode | `unicode-segmentation`, `unicode-linebreak`, `unicode-bidi` | корректный курсор и переносы |
| Модель | собственная: `Document → Block → Paragraph → Run` | контроль над undo/docx |
| docx | `zip` + `quick-xml` (свой парсер/писатель) | `docx-rs` — только как референс/быстрый старт экспорта |
| PDF | `printpdf` или `pdf-writer` + `subsetter`/`ttf-parser` | встраивание шрифтов, векторный текст |
| Изображения | `image` | PNG/JPEG |
| Орфография | `spellbook` (Hunspell на Rust) | чистый Rust |
| Диалоги ОС | `rfd` | открыть/сохранить |
| Анимации | встроенные GPUI `with_animation` + `lilt`/`keyframe` | пружины, цепочки |
| Цвет/иконки | `palette`, Phosphor SVG | тёмная тема, иконки |
| Dev-loop | `bacon`, `notify`, (`subsecond`) | живая пересборка |
| Прочее | `serde`, `thiserror`, `anyhow`, `tracing`, `slotmap`, `smallvec` | |

**Решено: остаёмся на `gpui-kit` (D-001).** Старое обсуждение для истории — **Про «gpui-kit»:** в `Cargo.toml` сейчас `gpui-kit = "0.7.3"`. Фактически основная библиотека — `gpui` (Zed) и готовые компоненты — `gpui-component` (longbridge). Предлагаю обсудить: брать `gpui` + `gpui-component` напрямую, а `gpui-kit` оставить, только если он вам нужен. ⚠️ Перед Этапом 0 проверить на docs.rs, какие версии согласованы между собой.

**Альтернативы (обсудить):** `egui` — проще, но хуже для сложной вёрстки текста и «Word-подобного» вида; `iced` — зрелый, но своё text-API слабее; `Slint` — не «чистый Rust-код» (DSL). Для редактора с кастомным canvas страниц **GPUI — хороший выбор**; риск — нестабильное API и слабая документация, поэтому изолируем его в `wv-ui`.

## 3. Архитектура
```
wordvolt (bin)
 └─ wv-ui      GPUI: окно, ribbon, canvas страниц, диалоги, ввод
     └─ wv-layout   текст → строки → страницы (cosmic-text)
         └─ wv-core    модель, Command, undo/redo, выделение, стили
 wv-io (docx/wvd/md/pdf)  → зависит от wv-core (и wv-layout для PDF)
```
**Ключевые решения**
1. Документ = дерево блоков; изменения только через `Command` (инверсия → undo/redo).
2. Позиция = `(block_id, byte_offset)` на границах графем; выделение = `anchor + head`.
3. Вёрстка инкрементальная: пересчёт только изменённого абзаца и последующих страниц; кэш шейпинга.
4. Свой canvas: страницы рисуются как GPUI `canvas`/кастомный `Element`, не как DOM из `div`; виртуализация — рисуем только видимые страницы.
5. IME и ввод: через GPUI `InputHandler` (важно для кириллицы/CJK).
6. Нативный формат `.wvd` = zip + JSON (serde), версия схемы в заголовке.

## 5. Риски
| Риск | Митигация |
|---|---|
| Нестабильное API GPUI | Изолировать в `wv-ui`, закрепить версии (`=x.y.z`) |
| Вёрстка текста — самая сложная часть | Строить на cosmic-text, не писать шейпинг самим; тесты на кириллицу/эмодзи/RTL |
| docx сложен и огромен | Поддерживать подмножество, расширять по реальным файлам |
| Производительность на больших документах | Инкрементальная вёрстка, виртуализация страниц, бенчмарки (criterion) |

## 6. Принятые решения (2026-10-17)
1. UI: **оставляем `gpui-kit`** (пересмотрим, если упрёмся в ограничения).
2. Платформы: **Windows, Linux, macOS** — не использовать платформенно-специфичный код вне `wv-ui`; CI-матрица на три ОС.
3. Форматы: **docx + любые текстовые** (`.txt`, `.md`, `.rtf`, `.html`, `.odt` — по приоритету); собственный `.wvd` остаётся внутренним форматом.
4. Язык интерфейса: **English + Русский**, i18n с самого начала (`fluent` / `fluent-templates`), строки не хардкодить.
