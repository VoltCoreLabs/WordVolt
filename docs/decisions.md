# Решения (ADR)

Формат: `ID — дата — решение`. Почему. Последствия. Менять только новой записью.

## D-001 — 2026-10-17 — Язык и UI-стек
Чистый Rust (edition 2024), UI на **GPUI** через **gpui-kit** (+ gpui-component). Не egui.
Почему: GPU-рендер, свободный кастомный canvas для страниц, анимации (`with_animation`). Альтернативы (Slint, Floem, Iced) — только план Б.
Последствия: GPUI изолирован в `wv-ui`; версии закрепляем. Прототип анимаций в Этапе 0 подтверждает выбор.

## D-002 — 2026-10-17 — Платформы
Windows, Linux, macOS. Платформенный код только в `wv-ui`. CI-матрица на 3 ОС.

## D-003 — 2026-10-17 — Форматы
docx + текстовые (txt, md, rtf, html, odt). Внутренний формат `.wvd` (zip + JSON).

## D-004 — 2026-10-17 — Язык интерфейса
English + Русский, i18n с начала (fluent). Строки не хардкодим.

## D-005 — 2026-10-17 — Структура файлов
Cargo workspace: `crates/{wv-core,wv-layout,wv-io,wv-i18n,wv-ui}` + `app/`. Файл ≤ 300 строк, большие делим. Подробно: `docs/structure.md`.

## D-006 — 2026-10-17 — Дизайн
Блочная система: светлый фон, блоки-панели, залитые кнопки с обводкой. Синий акцент `#2563EB`, радиусы 8/12/16, кнопки 32px, ribbon с вкладками. Только светлая тема сейчас, тёмная позже через токены. Подробно: `docs/design.md`.

## D-007 — 2026-10-17 — Git-воркфлоу
Задача = ветка → коммиты → проверки → PR → squash-merge при зелёных проверках. Подробно: `CLAUDE.md`.

## D-008 — 2026-10-17 — Доп. библиотеки UI
`lilt`/`keyframe` (сложные анимации), `palette` (цвет), Phosphor SVG (иконки, D-010), `rfd` (диалоги). План Б по UI — Slint.

## D-009 — 2026-10-17 — Живая пересборка (dev-loop)
Полноценного HMR как в Tauri у GPUI нет. Цель: изменил код → окно обновилось за секунды.
Слои: (1) `bacon`/`cargo-watch` — пересборка и перезапуск при сохранении; (2) быстрая сборка в dev (lld/mold, `opt-level=1` для зависимостей, incremental); (3) **hot-reload токенов темы** из файла через `notify` без пересборки; (4) эксперимент: `subsecond` (hot-patching Rust) — оценить в Этапе 0; (5) сохранение/восстановление открытого документа при перезапуске.

## D-010 — 2026-10-17 — Иконки: Phosphor
Набор иконок — **Phosphor** (SVG, лицензия MIT), вместо Lucide из D-008. Файлы в `assets/icons/phosphor/` (стили regular/bold/fill), рисуем через GPUI `svg()`. Подключать только нужные иконки, не весь набор.

## D-011 — 2026-10-17 — Dev-команда
`cargo dev` (алиас в `.cargo/config.toml` → `cargo watch -x run` по `crates/` и `app/`). `just`/`bacon` не нужны, `cargo-watch` уже установлен. Уточняет D-009.

## D-012 — 2026-10-17 — Шрифт по умолчанию: SF Pro Text
Шрифт UI по умолчанию — **SF Pro Text**, запасные: Inter (OFL, лежит в репозитории) → Segoe UI. Файлы SF Pro лежат локально в `assets/fonts/SFProText-*.ttf` и **в git не попадают** (`.gitignore`): лицензия Apple запрещает распространять шрифт, а репозиторий публичный. Следствие: у других разработчиков и в релизных сборках SF Pro не будет, пока не решён вопрос с лицензией — там сработает Inter. Решение «ставить ли SF Pro в релиз» — открытый вопрос.

## D-013 — 2026-10-17 — Undo/redo через Edit-splice
Каждое изменение = `Edit { at, removed, inserted, before, after }`: подмена диапазона абзацев (клонируются только затронутые). Выбрано вместо обратных команд: проще и надёжнее, обратимость гарантирована для любой операции. Позиции пока индексами абзацев (не id) — перейти на id при появлении таблиц/объектов.

## D-014 — 2026-10-17 — Язык интерфейса по умолчанию: русский
Все строки UI — через `wv-i18n` (`Key` + обе локали); по умолчанию `Lang::Ru`. Хардкод строк в виджетах запрещён. Следующий шаг: переключатель языка в настройках.

## D-015 — 2026-10-17 — Формат .wvd: JSON с версией (пока без zip)
`{"format":"wvd","version":1,"paragraphs":[{"align","runs":[{"text","bold",...}]}]}`. Читаем версии ≤ 1, более новые отклоняем с понятной ошибкой. Переход на zip-контейнер — когда появятся картинки (версия 2, обратная совместимость с 1). Запись атомарная (temp + rename).

## D-016 — 2026-10-17 — Плавные ховеры через слой-оверлей
GPUI `.hover()` мгновенный. Вместо обёртки элемента в AnimationElement (ломает цепочку `.on_click`) у элемента есть первый дочерний слой, который проявляется через `with_animation` (opacity, 140 мс). Состояние hover — глобальная карта по `ElementId` (`HoverMap`), поколение растёт при каждом входе/выходе и перезапускает анимацию. Правило: новые кнопки используют `track_hover` + `hover_layer`.

## D-017 — 2026-10-17 — docx: свой тонкий парсер на zip + quick-xml
Подмножество OOXML: прямое форматирование run (b, i, u, sz, color), jc абзаца, табы, разрыв строки = новый абзац, стили Heading/Title читаются как жирный; w:delText (удалённое) игнорируется; защита от zip-бомбы (лимит 256 МБ на document.xml). Пишем минимальный валидный пакет (Content_Types, rels, styles.xml с Calibri 11, A4, поля 2.5 см). Зависимости: zip 2 (только deflate), quick-xml 0.37 (0.38+ отдаёт сущности отдельным событием — при обновлении учесть). `docx-rs` не берём: нужен полный контроль над соответствием модели.

## D-018 — 2026-10-17 — Диалоги файлов: rfd
GPUI-диалоги не умеют фильтры типов файлов, поэтому Открыть/Сохранить как — `rfd::AsyncFileDialog` (родительское окно передаётся). Формат при сохранении определяется расширением выбранного пути; без расширения — `.wvd`. Подтверждения (Сохранить изменения?) остаются на `window.prompt`.

## D-019 — 2026-10-17 — Цель продукта: полный клон Word + свои функции
Решение пользователя: ориентир — функциональный паритет с MS Word (все вкладки ленты) плюс собственные функции. Карта задач — `plan.md §7`. Пересмотрено прежнее «не делаем»: совместная работа возвращается как отдалённая цель (CRDT), вместо VBA — собственный скриптовый движок. Порядок работ определяет фундамент: движок вёрстки, пагинация, стили, блоки (таблицы/картинки/списки) — без них функции ленты не построить.

## D-020 — 2026-10-17 — Свой движок вёрстки поверх измерителя шрифтов
GPUI `StyledText` не умеет разные размеры в строке, justify и страницы, а `TextLayout` ломает выравнивание. Решение: `wv-layout` делает перенос строк (unicode-linebreak), выравнивание и пагинацию сам, а ширины/метрики берёт из трейта `Measurer` (UI реализует его через GPUI shape_line). Плюсы: чистая тестируемая логика без GPUI, один источник координат для каретки/выделения/клика. Минусы: рисуем и измеряем фрагменты сами; кэшировать ширины. Не сделано: табуляции, висячие строки, bidi, переносы слов.

## D-021 — 2026-10-17 — Свои поля ввода вместо gpui-component Input
Для поля шрифта нужен ввод текста + выпадающий список с нашим дизайном. gpui-component тянет свою тему/Root; сделан минимальный `LineEdit` (ввод, стрелки, Home/End, Backspace/Delete, копирование/вставка, выделить всё) + `FontPicker` на `deferred(anchored())`. Ограничения: нет IME и выделения мышью в поле — добавить, когда понадобятся другие поля (размер числом, найти/заменить), тогда `LineEdit` станет общим компонентом.

## D-022 — 2026-10-17 — Расширенное форматирование текста (Telegram и шире)
Набор: bold, italic, underline, strike, mono (код), spoiler, quote (абзац), link, script (над/подстрочный), caps (только отображение), color, highlight, font, size. Решения: (1) спойлер скрыт блоком, пока каретка/выделение не касается его — удобно редактировать; (2) ссылка рисуется цветом акцента с подчёркиванием, стиль в модели не меняется, а набор текста сразу после ссылки не продолжает её; (3) caps не меняет текст в модели (иначе потеря исходного регистра), измерение и рисование идут через верхний регистр; (4) в docx спойлер не имеет аналога и теряется, моно сохраняется шрифтом Consolas, цитата — стилем Quote, ссылки — hyperlink + relationships; (5) последние цвета живут в `RecentColors` (глобально, до перезапуска).

## D-023 — 2026-10-17 — Тултипы: управляемая система gpui-kit вместо нативного `.tooltip()`
Нативный GPUI-тултип появляется мгновенно у курсора без анимации. Берём `TooltipOverlay` из `gpui_kit::base`: даёт задержку/льготный период/позиционирование и анимации; внешний вид — свой `TipView` (тёмная плашка, токены темы), анимации — те же `EffectTransition`, что у gpui-component. Ограничение: у элемента один `on_hover`, поэтому показ идёт через `on_mouse_move` + `on_prepaint` (границы кнопки), а скрытие — в `track_hover`; повторный запрос для той же кнопки отсекается по границам (`Active`), иначе анимация перезапускалась бы на каждое движение мыши. Правило: подсказки — только через `.tip()`.

## D-024 — 2026-10-17 — Списки как стиль абзаца, нумерация считается при вёрстке
Список — свойство абзаца (`ParaStyle.list` + `indent`), а не отдельный блок: проще редактирование (Enter/Tab/Backspace работают на уровне абзацев) и конвертация. Номера в модели не хранятся — их считает `wv-layout` (`Counters`): счётчик на уровень, сброс глубже при новом пункте и полный сброс на обычном абзаце, поэтому отдельный список после обычного абзаца начинается с 1. В docx каждый такой список получает свой `w:num` со `startOverride`, иначе Word продолжил бы нумерацию. Ограничения: нет стилей/форматов номера на пункт, нет «продолжить нумерацию», уровни до 8.

## D-025 — 2026-10-17 — Именованные стили: умолчания, а не копии форматирования
Абзац хранит только имя стиля (`ParaStyle.named`); размер/жирность/цвет стиль подставляет при вёрстке (`with_named_style`), пока в тексте нет прямого форматирования — поэтому смена стиля меняет вид без правки ранов, а ручной размер/цвет сильнее стиля. В docx заголовок — это `pStyle` со стилем в styles.xml (раньше читали как «жирный», теперь без потери смысла). Пока только встроенные стили; пользовательские потребуют таблицы стилей в `Document` (`StyleSheet`: имя → CharStyle+ParaStyle, наследование `basedOn`).

## D-026 — 2026-10-17 — Поиск в ядре, подсветка как слой отрисовки
Поиск — чистая функция над текстом абзацев (`wv-core::search`), результат — позиции (абзац, байтовое смещение), поэтому подсветка, выбор и замена используют одни и те же координаты. Подсветка — отдельный слой в `page_paint` (не стиль текста): документ не меняется, пока ищем. «Заменить все» — одна `Edit`-подмена диапазона абзацев (D-013), а не N операций, иначе отмена потребовала бы N нажатий. Панель пересчитывает совпадения по `revision` редактора, поэтому остаётся верной при вводе и отмене.

## D-027 — 2026-10-17 — Таблица как метка на абзацах, а не новый тип блока
`Document` остаётся плоским списком абзацев; ячейка — свойство абзаца (`Cell{table,row,col}`). Плюсы: не меняются позиции, выделение, undo, поиск, форматирование, форматы; вёрстка получает таблицы отдельным шагом (`blocks()`). Минусы: структура таблицы выводится из абзацев (строки/столбцы = максимумы индексов), нет вложенных таблиц и ширин столбцов (пока равные). Правка текста запрещена через границу ячеек — иначе слияние абзацев разрушило бы сетку; изменение структуры только командами меню (одна запись в истории).

## D-028 — 2026-10-17 — Колонтитулы как свойство документа, не абзацы
`Document.header/footer: Band{text}` — одна строка с токенами `{page}`/`{pages}`, рисуется в полях страницы (`editor/band_paint.rs`), вёрстку тела не меняет. Почему: полноценные колонтитулы (формат, разделы, первая/чётные страницы) потребуют отдельной модели; пока достаточно текста, который переживает .wvd/.docx. Правка через `set_header_footer`/`set_page` — один шаг отмены: `Edit.settings` хранит `DocSettings` (колонтитулы + страница) до/после рядом со сплайсом абзацев.

## D-029 — 2026-10-17 — Рисунок как блок-абзац со ссылкой на данные документа
`ParaStyle.image = ImageRef{id,width,height}` (px, 96 dpi) + `Document.images: Vec<ImageData{format, bytes}>`; абзац-рисунок не содержит текста, верстается одной строкой высотой в рисунок (`ParagraphLayout.image`), выравнивание — обычное абзацное. Почему: каретка, выделение, undo и пагинация работают без нового типа блока (как у таблиц, D-027); данные в `Arc` не копируются при undo. Ограничения: нет обтекания и плавающих, не внутри таблиц; текст нельзя печатать в таком абзаце, Backspace/Delete снимает рисунок, Enter добавляет абзац после.

## D-030 — 2026-10-17 — PDF: собственная вёрстка по метрикам встраиваемого шрифта
PDF строится в `wv-io/pdf` на `pdf-writer` + `ttf-parser`: документ верстается заново `wv-layout` с `Measurer` поверх TTF-файла (а не экранными метриками GPUI), поэтому строки гарантированно помещаются при выводе. Цена: разбиение на страницы может немного отличаться от экрана (шрифт интерфейса SF Pro/Inter заменяется системным Segoe UI/Arial). Шрифты ищутся в системных папках (`SystemFonts`, трейт `FontSource` позволяет подменить), встраиваются целиком; подмножество — позже.

## D-031 — 2026-10-17 — Редкие команды в меню строки заголовка
Файл/Правка/История вынесены из ленты в текстовые меню в заголовке окна (`MenuBar`, команды — enum `Command`, исполняет `MainWindow::run_command`). Почему: лента нужна для форматирования во время набора, а файловые и служебные команды используются редко и занимали место. Правило на будущее закреплено в CLAUDE.md.

## D-032 — 2026-10-18 — Орфография: spellbook + вшитые словари Hunspell
Проверка — крейт `wv-spell` на `spellbook` (чистый Rust, формат Hunspell). Словари ru/en лежат в `assets/dictionaries/` и вшиваются `include_str!` (ru ≈3.4 МБ), у каждого свой LICENSE (en — SCOWL, ru — А. Лебедев, см. файлы). Язык слова — по письму (кириллица → ru, латиница → en), без настройки языка абзаца. Почему: без внешних файлов и системных зависимостей, работает офлайн; цена — размер exe и фоновая загрузка словарей при старте. Пользовательские слова — `userdict.txt` в папке настроек.

## D-033 — 2026-10-18 — Буфер с форматированием: фрагмент в приложении, текст в системе
GPUI не умеет писать в буфер HTML/RTF, поэтому системному буферу отдаётся обычный текст, а форматированные абзацы хранятся в глобале `ClipFragment` рядом с этим текстом. При вставке формат берётся, только если текст буфера совпал с сохранённым (иначе скопировали в другой программе — вставляется текст). Работает между вкладками и окнами приложения. Формат для чужих программ — позже, через платформенный API буфера.

## D-034 — 2026-10-18 — CI: GitHub Actions на Windows

Проверки (fmt, clippy `-D warnings`, test) выполняются на каждый PR и пуш в `main` в `.github/workflows/ci.yml`, пока только на `windows-latest`: GPUI собирается на Windows без доп. системных библиотек. Linux/macOS добавим отдельной задачей (нужны системные зависимости GPUI). Локальные проверки перед мержем остаются обязательными.

## D-035 — 2026-10-18 — Плавающие рисунки: абзац-якорь + полоса «сверху и снизу»
Плавающий рисунок остаётся абзацем-рисунком (якорь в порядке документа), но берёт нулевую высоту; его положение хранится в px от текстовой области страницы якоря. Обтекание — «сверху и снизу» (строки обходят горизонтальную полосу рисунка), «перед/за текстом» (текст не двигается). Почему не обтекание по бокам: оно требует раскладки строк с переменной шириной в зависимости от положения на странице, то есть отказа от кэша раскладки абзацев; полоса работает на готовых раскладках. Какая страница у рисунка, зависит от текста перед ним, поэтому `paginate` повторяется до устойчивого положения (≤3 раза). Обтекание по бокам — отдельной задачей.

## D-036 — 2026-10-18 — Обтекание «вокруг рамки»: перекладка затронутых абзацев
Строки с переменной шириной нельзя получить из кэшированной раскладки абзаца, поэтому обычная вёрстка и пагинация идут как раньше (быстрый путь без плавающих рисунков не изменился), а при наличии рисунков с `Wrap::Square` затронутые ими абзацы перекладываются с препятствиями и поток повторяется (≤3 раза): положение препятствия зависит от абзацев выше, а высота перекладываемых абзацев — от препятствия. Высота строки для решения «влезает ли рядом» оценивается по стилю первого фрагмента. Поворот только на 90° (поворот пикселей без растеризации в PDF и без перевёрстки габаритов); произвольный угол — позже.

## D-037 — 2026-10-18 — Поворот рисунков: растр в вёрстке/UI, матрица в PDF
GPUI не рисует повёрнутые картинки, поэтому повёрнутый рисунок показывается заранее подготовленным растром (повёрнутая и обрезанная копия, ≤800 px, билинейная выборка), а в PDF рисунок остаётся исходным и поворачивается матрицей вокруг центра. Тот же растр (в 128 px) даёт контур для обтекания «по контуру». Расчёт растра живёт в `wv-layout` (`raster.rs`, зависимость `image`), потому что от него зависят и вёрстка (контур), и UI, и PDF-экспорт; `wv-io` не нужен вёрстке. Угол хранится в градусах, `width/height` — размер рамки до поворота, под текст отводится описанная коробка (`turned_box`).

## D-038 — 2026-10-18 — Режим жёсткой экономии токенов
Пользователь запретил скриншоты и живые прогоны: проверка идёт тестами (логика вынесена в ядро/вёрстку/форматы), а что видно только глазами, перечисляется списком «Проверьте сами». Почему: скриншоты, повторы правок и длинный вывод команд съедали основную часть бюджета. Правило записано в CLAUDE.md («Режим работы»).

## D-039 — 2026-10-18 — Разделы: конец раздела хранится в абзаце
Как в Word, свойства раздела лежат у его последнего абзаца: `ParaStyle.section = Some(id)`, а `PageSpec` — в `Document.sections[id]` (как `table_looks`), поэтому правки абзацев и отмена переносят разрыв сами. Вёрстка бьёт абзацы на диапазоны по разрывам и вызывает `paginate` для каждого со своим `PageSetup`, затем склеивает страницы (`Page.setup`); так не пришлось переписывать `paginate`. Сетка страниц в UI рассчитана по самой большой странице.

## D-040 — 2026-10-18 — Пользовательские стили: определение хранится в документе, вид — через `Document::resolve`
Стиль — `UserStyle` в `Document.styles` (как `table_looks`/`sections`), абзац ссылается на него через `ParaStyle.custom`; изменение стиля — один шаг отмены (`DocSettings`). Вёрстка получает абзац через `Document::resolve`: свойства стиля подставляются, только если абзац/текст не задали своё, затем встроенный стиль (поэтому стиль на базе «Заголовок 1» работает как заголовок). Из .docx берутся стили абзацев, которые реально используются, `basedOn` схлопывается в плоский `UserStyle`.

## D-041 — 2026-10-18 — Выпуск: тег `v*` собирает пакеты для всех ОС в GitHub Actions
Релиз делает `.github/workflows/release.yml` по тегу `vX.Y.Z[-суффикс]`: Windows (установщик Inno Setup `installer/windows/wordvolt.iss` + портативный zip), macOS (.app в .dmg, arm64), Linux (.deb + tar.gz); суффикс в теге делает релиз пре-релизом, описание — `docs/releases/<версия>.md`. Собирать на чужих ОС локально нельзя, поэтому сборка идёт на раннерах; изменения workflow/installer проверяются сборкой пакетов в PR без публикации. Сборки не подписаны (SmartScreen/Gatekeeper предупреждают) — сказано в описании. Исполняемый файл Windows — `WordVolt.exe`.
